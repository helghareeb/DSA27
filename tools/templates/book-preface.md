This book is the whole of DSA27 on paper: the fifteen lecture handouts, and after
each one the question bank for that week. The answers to every question are
together at the back, in Part III, with the practice papers.

**The order to use it in, each week.**

1. **Read the week's chapter before the lecture**, or straight after it. The
   handout holds everything on the slides plus what is said out loud.
2. **Do the lab.** The lab manual walks you through building that week's
   structure, one method at a time. The lab is where the course is learned.
3. **Answer the week's questions on paper, without a computer.** The final exam
   is written, on paper, with no computer: practise the way you will be tested.
4. **Only then turn to the answers** at the back. Mark yourself honestly, and
   look at which *kind* of question you lost marks on. Every question is tagged
   **[what]** (recall), **[how]** (apply) or **[why]** (explain and justify),
   and the exam leans on **[why]**.

**What the question codes mean.** `W8-M03` is week 8, multiple-choice question 3.
The letters are: **M** multiple choice · **E** short answer and essay · **T**
trace the code · **K** complexity analysis · **P** proofs · **R** recurrences ·
**S** draw the state after every step · **B** find and fix the bug · **C** write
the code. The **C** problems are real exercises in the course repository:
`practice/weekNN.py`, checked by `pytest`.

**The storage rule.** From Week 2 on, every structure you build keeps its data
only in the course `Array`, in node objects, or in another structure you built
yourself — never in a Python `list`, `dict` or `set`. Lecture 02 explains why.
You will see the rule at work in every chapter.

**The repository.** Everything in this book comes from
<https://github.com/helghareeb/DSA27>, where you also find the code skeletons,
the tests, the notebooks, the slides and the worked solutions. When the book
names a file such as `dsa/stack.py`, it is a file in that repository.

**Announcements** are on the course WhatsApp channel; video is on

**Honesty about the answers.** Every trace, output and number in the answers was
produced by running the code, not written from memory. If you find an answer you
believe is wrong, say so in the lecture or on the channel: you will be right
sometimes, and the book will be corrected.
